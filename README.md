# RAG over Apache Airflow documentation

A retrieval-augmented question-answering system over a pinned snapshot of
Apache Airflow's documentation, run fully locally (embeddings and
generation), with every reported number traceable to a saved result file.
Built to replace a prior, untested "RAG chatbot" resume entry with one that
has a measured evaluation behind it.

## Results (frozen test set, measured once)

40 test questions (33 answerable from the corpus, 7 adversarial), never
used for any design choice, run once with the configuration frozen on the
15-question dev set. The question set was built from a curated reading
packet of corpus excerpts with LLM-assisted drafting; every question was
edited by the author and its expected source verified against the pinned
corpus (see `docs/DESIGN.md`). Answers hand-graded by one
grader against written expected answers; partial = 0.5.

| condition | score (of 33) | adversarial declined |
|---|---|---|
| closed-book (model only, told the topic is Airflow) | 15.5 (47%) | 0 of 7 |
| retrieval-augmented (this system) | 20.5 (62%) | 4 of 7 |

- Retrieval on the test set: hit@5 0.788, MRR 0.602 (0.917 / 0.722 on the
  dev set it was chosen on).
- Of the 14 RAG answers that were wrong or partial: 7 retrieval misses,
  2 cases where the right file was retrieved but not the answering
  sentence, 5 generation errors (3 contradict their own excerpts).
- Retrieved-excerpt faithfulness: 26 of 33 answers fully supported.

Caveats: 33 questions and a single grader, so one grade moves the score by
about 1.5 points. Two adversarial items (a046, a047) have related material
in the corpus despite their "no answer" label, and one answer key (d026)
is incomplete; these are recorded in `docs/DESIGN.md` and were not edited,
because the test results had already been seen.

Full per-answer grades with reasons: `results/test_grades.json`.

## How it works

| part | choice | why |
|---|---|---|
| Corpus | Airflow commit `2f84606`: core docs, docstrings, changelog fragments, 5 provider doc trees (570,658 words, 1,173 files) | Apache-2.0, pinned and hashed; see `docs/CORPUS_LICENSE.md` |
| Chunking | fixed window, 200 words, 40 overlap (4,171 chunks) | beat structure-aware chunking on every retrieval method on dev |
| Retrieval | dense, `BAAI/bge-small-en-v1.5`, FAISS inner product, top 5 | beat BM25 and hybrid (RRF) on dev |
| Generation | `qwen2.5:7b-instruct-q4_K_M` via Ollama, temperature 0, seed 42, `num_ctx` 8192 | tied with `llama3.1:8b` on dev; chosen by a rule fixed before the run |
| Prompt | "You are answering questions about Apache Airflow." plus: answer only from the excerpts, say so when they don't cover it | grounded answers and declines on out-of-corpus questions |

Every decision, the alternatives rejected and the measurements behind them
are in `docs/DESIGN.md`, including findings along the way: the first
choice of model (`gemma-4-31b-it` on a free hosted API) failed on backend
capacity; Ollama's default context window silently cut long prompts to
about 2,050 tokens; and four mislabelled eval questions were corrected
before any test result existed.

## Running it

Requirements: Python 3.12, [Ollama](https://ollama.com), about 15 GB of
disk. Developed and measured on Windows 11 (Intel i7-7600U, 16 GB RAM, no
GPU), where one `/ask` takes about 3 minutes.

The corpus is not committed. Regenerate it from the pinned Airflow commit
(the script refuses any other commit):

```
git clone https://github.com/apache/airflow.git
git -C airflow checkout 2f846065252579d4ef8729ba8e42d96c5ab1b611
python mlops/extract_corpus.py --repo-root airflow --out corpus
```

Then:

```
ollama pull qwen2.5:7b-instruct-q4_K_M
python -m venv scripts/venv
scripts\venv\Scripts\activate            (Windows)
pip install -r service/requirements.txt
python -m pytest tests -q
cd scripts/src
python build_index.py ../../corpus      (about 20 min on CPU; checks it reproduces the evaluated retrieval)
cd ../..
uvicorn service.app:app --host 127.0.0.1 --port 8000
```

Endpoints: `GET /health`, `POST /retrieve` (`{"question": ...}`, excerpts
only, no model call), `POST /ask` (`{"question": ..., "include_excerpts":
false}`, answer, sources, model digest, settings, timing).

Reproducing the evaluation (from `scripts/src`):

```
python run_comparison.py ../../corpus ../../eval/questions.json             chunking x retrieval comparison (dev)
python retrieve.py ../../corpus ../../eval/questions.json --split test      frozen retrieval
python context_check.py --model qwen2.5:7b-instruct-q4_K_M                   context window check
python rag_answer.py --model qwen2.5:7b-instruct-q4_K_M --split test
python closed_book.py --model qwen2.5:7b-instruct-q4_K_M --split test --framed
```

Runs log to a local MLflow store (`mlflow.db`, not committed); every
result file is in `results/`.
